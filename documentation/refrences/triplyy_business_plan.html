01 — Product overview

What is Triplyy?

Triplyy is a travel deals micro SaaS that takes a traveler's trip details (destination, dates, budget, preferences) and delivers curated hotel, hostel, and flight deals to their email inbox and dashboard. It is positioned as a personal travel deals concierge rather than a booking engine.

The core insight: travel APIs are queryable by anyone, but filtering, ranking, and delivering the right deals for a specific person's trip profile in a clean, scannable digest is the actual product. That curation layer is the value, not the raw data.

The free tier does the selling for you. A well-formatted digest of real deals for an upcoming Istanbul trip makes paying $9/month feel like nothing.

Problem being solved

Travelers waste hours across Booking.com, Skyscanner, Google Flights, and Hostelworld each week, manually filtering for deals that match their specific trip window, budget, and travel style. There is no tool that learns a trip profile once and continuously surfaces relevant deals automatically.

Solution

Triplyy ingests a user's trip profile once (via a short form) and becomes a passive deal-scanner running in the background. Paid users receive weekly email digests and have access to a dashboard where deals are aggregated, filtered, and ranked. Pro users additionally receive an AI reasoning layer that evaluates deals against their travel style and explains why each pick fits them.

02 — Business model

How Triplyy makes money

Triplyy is a pure subscription SaaS. Revenue comes from monthly subscription fees. There are no referral commissions or affiliate markups in v1 (though these can be layered in later as a secondary revenue stream).

Value ladder

Each tier is designed to sell the next one. The free tier converts to Basic by demonstrating value with a real sample digest. Basic converts to Pro by surfacing the AI upsell in every email footer and dashboard header.

API data (flights, hotels) appears "free" on Booking.com to the end user. The real product is automated filtering, personalized delivery, and AI reasoning — none of which are available for free elsewhere.

Deal sources: recommended approach

Use travel APIs (Amadeus, Booking.com Affiliate, Skyscanner RapidAPI) for real-time data on the Free and Basic tiers. The AI reasoning layer on Pro uses those same results as input and passes them through an LLM (Claude API or GPT-4o) to generate ranked recommendations with written explanations. This keeps infra cost predictable and scales AI cost only where it is being charged for.

05 — Auth and onboarding

Authentication model

Triplyy uses passwordless email authentication only (magic links). No social login, no password creation. This reduces friction at signup and eliminates password reset flows entirely.

How it works

On the /login page, a user enters their email and clicks "Send me a link." An email with a time-limited (15-minute) magic link is sent. Clicking the link authenticates the session and redirects to the dashboard. The session is maintained via a long-lived JWT stored in an httpOnly cookie (30-day expiry, refreshed on activity).

Recommended implementation: Supabase Auth with magic link enabled. Zero custom auth code, built-in email templating, and RLS integration with the rest of the data layer.

Access control by tier

Route-level middleware checks subscription status on every dashboard request. Unauthenticated users are redirected to /login. Authenticated Free users are redirected to the upgrade teaser page (/upgrade). Authenticated Basic/Pro users access the full dashboard at /dashboard.

Profile management (Basic and Pro only)

Authenticated paid users can edit their profile from /dashboard/profile: name, email (triggers re-verification), billing management link (Stripe Customer Portal), notification preferences (email frequency, digest day preference), and subscription details.

06 — Technical stack

Recommended stack

Frontend

Next.js 14 (App Router), Tailwind CSS, shadcn/ui components. Deployed to Vercel.

Backend / API

Next.js API routes or Hono (lightweight). BullMQ for digest job queue. Redis for rate limiting and job state.

Database

Supabase (PostgreSQL). Prisma ORM. Tables: users, trips, deals, digest_logs, subscriptions.

Auth

Supabase Auth, magic link only. JWT sessions, httpOnly cookies. Middleware on /dashboard/* routes.

Travel data

Amadeus API (flights), Booking.com Affiliate API (hotels/hostels). Rate-limit-safe via job queue.

AI layer (Pro)

Claude API (claude-sonnet-4-20250514). Deals passed as context, AI returns ranked list + reasoning JSON.

Email

Resend (transactional) + React Email for digest templates. Magic link emails via Supabase Auth SMTP.

Payments

Stripe. Subscription webhooks update subscription status in DB. Stripe Customer Portal for self-service billing.

08 — Go-to-market

Go-to-market strategy

Phase 1: content and community (months 1-3)

Post in r/solotravel, r/digitalnomad, r/backpacking, and travel-focused Facebook groups. Frame posts as "I built a tool that sends you filtered hotel and flight deals for your upcoming trip." Share the free tier link. These communities are highly receptive to genuine tools built by solo developers.

Phase 2: SEO (months 2-6)

Target long-tail keywords: "cheap hostels Istanbul October," "budget flights Tunis Cairo." Create a blog section on triplyy.app publishing destination-specific deal roundups weekly. These rank well and funnel readers to the free intake form.

Phase 3: partnerships (months 4+)

Reach out to travel YouTubers and travel bloggers in the budget/backpacker niche for affiliate partnerships. Offer them a % of subscription revenue for referrals. A single mid-size travel creator mention can generate hundreds of free signups.

The product is its own best marketing tool. Every free digest email that lands in someone's inbox is a marketing touchpoint. Making those digests genuinely good is the best growth strategy.

09 — Risks and mitigations

Key risks

High
Travel API rate limits and costsAmadeus and Booking.com APIs have rate limits and usage quotas. A large user base can quickly exhaust free tiers. Mitigation: use BullMQ job queue to batch requests, cache results for 4-6 hours, and only fetch fresh data within 48 hours of a digest send.
High
Email deliverabilityDigest emails going to spam destroys the product's core value. Mitigation: use Resend (built for transactional email), authenticate the domain with SPF/DKIM/DMARC, and warm up the sending domain gradually. Include a clear unsubscribe link in every email.
Medium
Low free-to-paid conversionIf the free digest is not compelling enough, paid conversion will be poor. Mitigation: A/B test digest format and deal selection logic. Ensure the free digest shows genuinely good deals, not leftover inventory.
Medium
AI cost at scale (Pro tier)If Pro AI reasoning is called too frequently, Claude API costs can erode margins. Mitigation: cache AI reasoning results per digest run (don't re-run AI on every page load). Cap on-demand refreshes at 3/day per user.
Low
Competition from large playersGoogle Flights and Booking.com could theoretically add digest features. However, they are not incentivized to remove users from their platforms. Triplyy's advantage is personalization depth and email-first delivery, not raw data access.
